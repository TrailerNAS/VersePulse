# VersePulse Vision

**Version:** 1.0  
**Status:** Active

---

# Mission

Build the best desktop companion for Star Citizen by providing accurate, real-time telemetry and useful tools without modifying the game or violating Cloud Imperium Games' Terms of Service.

VersePulse exists to give players meaningful information—not unfair advantages.

---

# Vision

VersePulse should become the companion application that every Star Citizen player installs.

The application should feel like a natural extension of the game by providing useful information in a clean, modern, and lightweight interface.

---

# Core Principles

## Read-Only

VersePulse will never:

- Inject into the game
- Read game memory
- Modify game files
- Automate gameplay
- Bypass anti-cheat systems

VersePulse only reads publicly available data generated by the game, such as `Game.log`, and uses standard Windows APIs.

---

## Performance

Performance is a feature.

Goals:

- Startup under 2 seconds
- Idle CPU usage below 1%
- Low memory usage
- Responsive UI
- Non-blocking background processing

---

## Reliability

VersePulse should:

- Recover automatically if Star Citizen closes
- Detect launcher restarts
- Handle missing log files gracefully
- Never crash because the game isn't running

---

## Simplicity

Configuration should be minimal.

A new user should be able to:

1. Install VersePulse
2. Launch it
3. Launch Star Citizen
4. Everything works automatically

---

## Modularity

Every major feature belongs in its own module.

Examples:

- Telemetry
- Performance
- Trading
- Mining
- Salvage
- Cargo
- Navigation
- Medical

Modules consume telemetry but never parse the game log directly.

---

# Architecture Philosophy

One source of truth.

```
Star Citizen
      │
      ▼
 Game.log
      │
      ▼
 LogReader
      │
      ▼
 Parser Pipeline
      │
      ▼
 Telemetry Engine
      │
      ▼
 TelemetryData
      │
 ┌────┼─────────┐
 ▼    ▼         ▼
 UI Overlay   Modules
```

The Telemetry Engine owns the game state.

Every other part of the application consumes telemetry from it.
